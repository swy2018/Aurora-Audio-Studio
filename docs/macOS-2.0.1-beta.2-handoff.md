# Mac 2.0.1-beta.2 构建与验收交接

基线为 `7b61bbd` 之后的 Beta 2 修复提交；以 v2.0.1-beta.2 标签为准。Windows 侧不提供未经 Mac 原生验收的 DMG，现有 Mac Beta 1 与正式版 2.0.0 继续可用。

## 已修改的 Mac 路径

- 保存设置先校验；主题等设置不结束工作台。活动工作台/任务阻止运行目录与安全模式变更；工具开始/重试不会静默杀掉工作台。
- 分轨手选模型同步模式，自定义模式切换选择兼容模型，执行前拒绝不匹配。
- 工作台通过独立实例标识、Gradio config 与操作 DOM 检查后才显示已连接。
- 环境修复创建 `envs/<family>-<uuid>`，依赖/导入检查通过后原子替换 `<family>.active`。旧 `envs/<family>` 仍受支持，不搬动 venv，不删除旧环境。
- 运行、权重随包提取与验收脚本均解析活动环境。模型权重 receipt 记录环境目录；权重回退不等于环境回退。
- 按已解析的仓库版本和文件清单隔离 staging；旧候选保留在 `staging-abandoned-*`，不把撤销文件混入新版。
- 更新检查仍只覆盖可追踪权重，不宣称 Git 代码/PyPI 依赖已经更新。

## 构建前

阅读 `docs/macOS-release.md`。先核对源码标签和本机系统/架构，使用新的构建目录；不能复用 Windows 编译输出、Python 虚拟环境或模型状态。保留用户配置、作品、模型和既有安装。

## 必须在 Mac 补做

1. 执行 MacTests、Python `test_environment` 和 `test_lifecycle`；Windows 共享测试、Linux POSIX 测试都不是 Mac 原生验收。
2. 在一次性小型环境中验证安装失败/取消不改变旧环境，成功切换后解释器路径、导入、权重随包提取和再次修复正常。不得用大模型全量重装代替边界测试。
3. 已有音乐/配音工作台输入与生成期间，保存主题、无效路径、有效路径、运行工具/重试；确认保护提示、输入保留和显式释放入口。
4. 真正启动各已支持的 Gradio 工作台，确认实例标识与 DOM 检查通过；试验假成功页面、初始化延迟、取消和再次进入。
5. 核对手选 Demucs/二轨引擎/多轨引擎与 custom 模式的显示、参数和真实音轨集合。
6. 导入坏项目和正常旧项目；批次完成期间保存草稿，确认索引、任务 ID 与原文件完整。
7. 运行代表性短素材并保存证据，再按现有流程签名、公证、装订、验证 DMG 和最终 SHA-256。

在相同 Release 补充 Mac 资产时保留 Windows 包和校验文件；更新平台文案与真实下载清单。失败或未验证项必须如实记录，不能把本文件当作通过证明。
