# ADR 0005: Application-owned first-install tools

Status: Implementation accepted; native clean-machine acceptance pending (2026-10-08)

## Context

Windows 2.0.1 could wait indefinitely while WinGet downloaded FFmpeg, before reaching the selected model. Developer-machine inference did not test first installation. Git was assumed to exist, and Whisper weight installation did not install its shared executable. The Mac bundle carried four tools but omitted Git and its HTTPS transport; an interrupted manager package installation could leave an unusable Python directory that subsequent attempts treated as ready.

## Decision

- Ship uv, Git, FFmpeg/ffprobe and SoX with the application. Windows build-time downloads use pinned upstream URLs and SHA-256 values, retain licenses and reject HTML download pages or changed bytes. Mac collects native tools and their libraries, Git helpers/templates/CA, then checks startup without Homebrew environment paths.
- Bundle Microsoft's signed Visual C++ x64 redistributable as a prerequisite. Verify its pinned hash, signature and version at build time. Inno Setup skips the same/newer installed runtime, requests no automatic reboot, and stops before replacing Aurora when the prerequisite fails or requires a restart. Never execute the redistributable on the development machine just to validate its packaging.
- Bundle the official WebView2 x64 standalone installer as well. Check the documented machine/user `pv` registrations and install only if absent. Do not assume that Windows or the Edge browser provides the runtime. Both prerequisite installers belong inside the setup payload, not the installed application's runtime directory.
- No WinGet, Homebrew, Xcode command-line-tools or system Python setup on an end-user machine. Build machines still need their normal native development toolchain.
- Use managed Python for new model environments, rooted below the configured model directory. Child-only PATH changes are idempotent; do not mutate global or parent PATH. Existing working model environments remain usable and are not reinstalled by this change.
- New Windows candidates use `.aurora/envs/<id>` below the model root. A real first install exposed a native CUDA DLL path-length failure in the previous deeper directory layout. Reject excessively long roots before creating files; retain logical selectors and existing environment paths without moving them.
- Resolve ordinary Windows model packages with matching CUDA-enabled PyTorch wheels in one operation. Do not first download CPU wheels and then replace them. F5 additionally selects the hash-pinned Windows CPython 3.11 TorchCodec 0.7 wheel from PyPI: the CUDA index lacks that Windows wheel. This does not change the inference device to CPU. Keep model-specific compatibility decisions separate from unrelated engine upgrades.
- Both F5 profiles require Datasets 3 or newer. A real isolated Windows import failed with Datasets 2.14.4 and PyArrow 25 despite successful dependency resolution; the older package references PyArrow's removed `PyExtensionType`. The corrected profile subsequently passed a complete Windows first install and short generation test; native Mac validation remains separate.
- TransKun must not compile NCLS on end-user machines. Windows uses the official CPython 3.11 NCLS 0.0.68 wheel with NumPy 1.x; Mac keeps the official ARM 0.0.70 wheel. Use `--only-binary=ncls` and validate the FNCLS overlap API that TransKun actually calls. No locally borrowed or anonymously hosted wheel is used.
- MiniMax resolves its fixed Diffusers commit, dependencies, torch 2.8 and torchaudio 2.8 with the CUDA index in one command. A real dry-run proved that the former unconstrained second `--upgrade` would replace CUDA torch with the CPU build. This check does not install MiniMax weights or certify its inference.
- Windows application-owned Git uses child-only Schannel, certificate verification and `core.longpaths`. Real tests exposed OpenSSL CA loading failures under a Unicode path and checkout failures in a long uv cache path. Preserve unrelated Git configuration and never change global Git settings, system certificate validation policy or Windows registry settings for this purpose.
- YourMT3 downloads its exact official 0.2.0-registry checkpoint over HTTPS with pinned revision, length and SHA-256, instead of requiring end-user Git LFS or cloning a full Space. Failed verification leaves existing weights unchanged. Windows pins Transformers 4.44.2 because a real fresh 5.x environment cannot import the vendored T5 implementation. Mac retains its existing 4.45.2 constraint; both platforms probe the actual inference module before activation.
- Hub commands distinguish explicit filenames from wildcard filters. Current `hf` treats `--include` as a repeatable single-value option; using it once before several values silently changed which Seed files were downloaded. Seed/SoulX now use positional filenames; MiniMax repeats the filter option for each pattern. MiniMax validation remains dry-run only.
- Health checks resolve legitimate Hugging Face cache symlinks before testing file length; empty and dangling targets remain invalid. ACE readiness requires recognized model weight filenames and all shards in an index, not merely an auxiliary tensor. Incomplete ACE downloads bypass upstream's directory-exists early return using `--force`; its underlying snapshot downloader still resumes/reuses cache. Complete components do not get that flag.
- Prepare the shared Whisper executable before downloading Whisper weights. Reuse an existing executable. Repair interrupted Mac manager dependency installation before executing lifecycle commands.
- Windows install confirmations include missing shared-runtime downloads and disk headroom. The actual Whisper shared runtime plus Small weights occupies about 5.2 GB of file contents, already exceeding the previous 1 GB recommendation before counting the retained archive. Qwen and Piano also require multi-GB Python/CUDA dependencies. Preserve the weight-only estimate when an existing shared Whisper/Qwen runtime is present; Piano always creates a new candidate environment. These remain estimates, not guarantees for future upstream package sizes.
- Preserve cancel/retry and candidate activation boundaries. Maintenance commands have a four-hour ceiling and ten-second elapsed-time feedback; Windows streamed downloads stop after sixty seconds without received data. Do not represent a heartbeat as byte progress or promise that a blocked source is reachable.
- Python output is explicitly UTF-8. Preserve complete raw maintenance lines in logs rather than truncating them at 180 characters.
- Demucs 4.1.0 omits NumPy from its Windows metadata despite importing it. Supply it explicitly; Mac also makes the constraint explicit and imports its actual separation API. A successful dependency resolver/check alone is not runtime acceptance.
- Keep Numba's default JIT behavior in the Windows Piano child. The prior forced `NUMBA_DISABLE_JIT=1` reproducibly breaks Librosa's `pad_center` import; a same-environment single-variable comparison and complete CUDA transcription validate the fix. No external developer compiler or global environment setting is added.
- Mac installation and maintenance share one inference-import table. A stale copied YourMT3 top-level-only probe must not overwrite a failed inference environment with a healthy record. The regression verifies failure persistence, not only a constant string.
- Awaited command cancellation must terminate its owned process tree and join exit in `finally`, with a bounded cleanup wait, before returning. `WaitForExitAsync(token)` only cancels waiting; a disposable callback that invokes asynchronous `Kill` is not sufficient evidence of exit. A real Basic Pitch timeout left uv alive; both a short process-tree fixture and real offline uv reproduced the former failure. Do not silently discard termination errors or claim cancellation finished while the owned command is still alive. Long-lived workbench lifecycle control remains separate.

## Consequences

Installers are larger. Published packages must include the verified tools, libraries, notices, and redistribution/source materials required by upstream licenses. Windows publishing fails if required tool executables are missing. Missing or damaged bundles produce an application-repair error, not instructions to configure a development machine.

An empty PATH test does not simulate a pristine OS, absent Visual C++ runtime, driver support, quarantine, signing, or platform-specific wheels. Native Windows and Mac first-install and inference acceptance remain release gates. Current targets remain Windows x64 and Apple Silicon/macOS 26+; this does not add Intel Mac support or turn download-only catalog items into inference engines.
