# Aurora 2.0.0 自有运行文案与日志

## 范围与原因

Windows 的部分后端结果和启动日志直接写入英文，模型维护日志将自有阶段与原始输出拼在一起；界面翻译并不覆盖写入磁盘的这些内容。本轮复用 LocalizationService，不引入新的翻译服务。

- 引擎启动、连接、内存不足、未安装、启动超时、退出失败和日志读取提示使用四语言词条。
- 任务日志增加带时间的 [Aurora] 开始、完成、失败、取消记录；保留数字退出码。
- 模型维护日志将自有阶段与原始输出分行，补齐安装、下载、校验、运行环境配置等阶段说明。
- Mac 源码增加本地化引擎日志说明及维护开始/结束记录；写入说明失败时报告错误，不阻止原有运行状态清理。
- 上游 stdout/stderr、Python traceback、原始路径和内部事件标记不翻译、不改写。历史日志不重写，语言设置只影响之后新写入的自有记录。

没有把未知错误一律改成成功，没有改动模型权重、推理参数、退出码、任务结果契约或版本回退策略。原始诊断信息可能仍为英文，这是保留排障信息的明确边界，不代表四语言自有提示被跳过。

正式版同步时另修复了更新日志脚本的版本边界：2.0.0 不得匹配 2.0.0-beta.*。已有历史条目已逐字核对保留，并加入回归保护。TransKun 安装顺序检查改为验证对应函数内的实际安装调用，不再依赖中文进度文案。

## 验证

RuntimeCopyRegression 通过真实隔离子进程验证四语言成功、失败、取消和结果收集，检查原始 stdout/stderr、文件路径、格式占位符与 failed: 内部事件保持不变。模型维护使用只返回空清单的测试传输，不联网安装模型。新增 61 项检查纳入现有 BehaviorTests 默认入口。

本机共享 Core 编译与既有回归通过。Windows 正式安装包仍必须通过发布工作流的完整构建、更新流程、行为/四语言/目录验证和隔离安装后启动检查；发布资产信息以正式 Release 及构建日志为准。

本轮没有重新运行全部模型推理，也没有完成 Mac UI、签名或安装验收。Mac 需按 2.0.0-mac-handoff.md 继续验证。

## 平台与发布

Windows 2.0.0 为本次正式发布目标。Mac 2.0.0 源码同步，但当前 Mac 正式安装包保留 1.9.9，Beta 4 保留。官网按平台独立选择完整安装包及校验文件，不能把 Windows 新版本当作 Mac 安装包。

Windows 仍未代码签名，不生成临时自签名证书代替正式签名。本轮是本地桌面应用文案及日志维护，无新云服务、数据库、账户、遥测或网络接口；相应云部署指标不适用。
