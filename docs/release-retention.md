# 版本保留说明

## 持续执行的发布保留规则（2026-10-05 更新）

1. 正式版发布成功并完成适用的签名／公证、安装验收与公开下载校验后，将所有版本号更旧的 Beta Release、其全部资产及已确认归属的旧草稿列入准确清理清单，获批后执行。同版本 Beta 也早于正式版；按完整版本顺序比较，不按上传时间判断。更高版本的 Beta 不属于本次清理范围。
2. 保留全部正式版发布、完整云端 Git 提交历史、现有分支和 Git 标签；不得随 Release 默认删除标签。确需删除 Beta 标签时，须单独列明标签、目标提交和影响并取得明确批准，同时确认提交仍能从保留的云端引用访问；禁止截断历史或强制推送。
3. 本地交付产物按产品、平台与架构只保留最新已验收安装包。旧安装包、校验文件副本、无用构建／测试产物、工作应用副本及冗余发布证据列入获批清理；保留精简的发布校验和清理回执，必要结论同时记录在 Release 和仓库文档。
4. 开发源码、本地 Git、工具链、凭据与签名配置属于必要发布环境，继续保留。已安装应用、模型、个人设置及作品不属于发布产物清理范围。
5. 每次构建完成后必须整理准确清单、保留项和影响，按用户 AGENTS.md 取得该清单的批准后执行；同一清单已获批准时不重复询问。清理后核对所有目标、受保护文件和云端下载入口，不把未删除的文件报告为已清理。

以上规则用于后续发布，优先于下方历史记录中的旧保留方案。
