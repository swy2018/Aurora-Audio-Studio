## 优先问题

所有代码位置相对于仓库根目录，行号对应本次工作区。P1 为可能中断任务、误导就绪状态或影响文件位置；P2 为行为不一致、错误状态和条件性风险。

### F1 · P1：不是工作台的网页也会被判定连接成功

- 位置：`work/audio-studio/AuroraAudioStudio/Services/BackendService.cs:598`、`:619`；`work/audio-studio/AuroraAudioStudio/MainPage.xaml.cs:247`。
- 实证：本地临时 HTTP 服务只返回普通 HTML，没有 Gradio 或任何创作控件；给定关联进程仍存活的前提，实际 `WaitForUrlAsync` 返回成功及“Connected to the local model.”。
- 原因：服务探测只认 HTTP 200/302，WebView 后续只检查导航成功；两者都不证明控件存在或响应来自正确引擎。
- 影响：端口冲突、错误页面或前端未就绪时可能显示“已连接”。本探针验证了判定漏洞，不表示已复现用户截图的全部成因。
- 建议：验证服务身份、监听进程及工作台就绪契约；最终检查所需输入、提交、结果控件后再显示可操作。

### F2 · P1：切换创作引擎可能直接中止另一项生成

- 位置：`BackendService.cs:76`、`:102`、`:129`、`:153`、`:174`（同上 Services 目录）。
- 源码确认：启动音乐或配音会停止 singing；启动 Seed-VC 会停止 music、voice。停止逻辑结束对应进程树，调用前没有当前生成任务完成条件或交接确认。
- 影响：另一工作台仍在生成时，切换功能可能丢失未完成结果。未运行真实模型复现中断。
- 建议：维护生成状态，运行中阻止切换或明确确认中止；只释放属于该任务的资源，不能用静默结束引擎代替资源调度。

### F3 · P1：修改存储路径的保护漏掉模型维护及暂停队列中的重试

- 位置：`MainPage.xaml.cs:1228`、`:1459`。
- 源码确认：现有保护检查 `utilitySubmissionBusy` 和 `backend.HasActiveOperations`，没有检查模型维护锁或等待执行的重试任务。维护由另一服务拥有，暂停的重试尚无后端进程。
- 影响：这些条件下可修改路径，而后续步骤仍读取当前设置，存在继续安装或登记结果时路径改变、旧项目找不到的风险。没有用真实安装或用户目录验证损坏。
- 建议：操作开始时冻结路径，并统一检查维护、排队和运行状态；路径迁移应是单独明确的操作。
- 已排除误报：普通正在运行的后端任务已有路径变更保护，并非所有场景都没有保护。

### F4 · P2：上轮补丁的静默检查占锁却不可取消

- 位置：`MainPage.xaml.cs:1614`。
- 源码确认：启动静默检查取得共享 `updateFlow`，调用 `CheckAllAsync(null, CancellationToken.None)`，没有可见取消入口。期间手动安装、检查及应用更新可能被忙碌状态拒绝。
- 这是上轮互斥修复引入的交互回归，不能将上轮补丁直接视为已具备发布条件。
- 建议：手动维护能取消并接管静默检查，同时拒绝旧检查回写；不能简单移除互斥。增加慢网络下的接管回归。

### F5 · P2：“任务完成后释放显存”开关没有接入执行逻辑

- 位置：`MainPage.xaml.cs:1241`、`:1411`；`Models/AppModels.cs:16`；Mac `MainWindow.cs:280`。
- 全局检索确认：`AutoReleaseVram` 只有定义、读取显示和保存，没有后端完成或资源调度消费点。
- 影响：切换此选项不会改变 Aurora 的引擎释放策略。部分上游可能自行卸载，因此不推断实际显存数值或所有引擎都不释放。
- 建议：实现并验证各引擎的任务结束卸载契约；不支持时禁用并解释，不展示无效承诺。

### F6 · P2：失败任务旧进度串入重试

- 位置：`Services/TaskQueueService.cs:72`、`:129`；`MainPage.xaml.cs:1459`。
- 实证：第一轮排队的 85% 回调被延迟，在同一任务记录开始重试、进度为 3% 后执行，进度变为 85%，阶段变成 `OLD_ATTEMPT_PROGRESS`。
- 原因：重试复用记录；回调只认 Running/Preparing，没有检查所属执行轮次。
- 建议：每轮执行绑定独立身份及可结束的进度接收器，结束后拒绝该轮排队回调。
- 修正上轮审查边界：现有保护确实能挡住“已完成状态”的迟到回调，但挡不住复用记录后的重试。

### F7 · P2：手动选择分轨引擎后，轨道模式可能与实际执行不一致

- 位置：`MainPage.xaml.cs:490`、`:575`；`Services/BackendService.cs:215`。
- 源码确认：预设会选择模型，但手动换模型只更新按钮状态，不同步轨道模式；轨道模式存入记录，却不传给执行函数。Demucs 命令没有两轨选项。
- 影响：界面保留“两轨”而手动选 Demucs 时，执行参数不保证两轨输出。没有做真实分轨推理。
- 建议：限定兼容组合、同步选择状态，或实际传递并执行轨道参数。
- 已排除误报：预设本身会映射模型，不能将所有质量预设都认作无效。

### F8 · P2：成品丢失后“打开所在位置”可能创建同名目录

- 位置：`MainPage.xaml.cs:1503`；`Services/BackendService.cs:553`。
- 源码确认：`File.Exists` 为 false 时，把完整文件路径当目录交给 `OpenFolder`；后者调用 `Directory.CreateDirectory`。
- 影响：已被移动或删除的 `audio.wav` 可能变成同名目录，而不是显示文件丢失提示。为避免弹出资源管理器，未执行该 UI 路径。
- 建议：区分文件和目录；不存在时提示并只允许打开现存父目录，导航操作不能创建成品路径。

### F9 · P2（条件性）：诊断包只做路径脱敏，没有凭据字段脱敏

- 位置：`Services/BackendService.cs:538`。
- 合成实证：用户目录被替换，但虚构的 `Authorization: Bearer`、`hf_token` 字段仍保留。
- 边界：没有读取或发现真实凭据泄露；现有预览文案也只承诺路径/用户名处理。风险前提是上游日志包含凭据、用户随后分享诊断包。
- 建议：增加常见凭据字段的脱敏回归，保留分享前预览，不自动上传诊断包。
